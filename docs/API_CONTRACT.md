# API Contract — v1

Base path: `/api/v1`

All errors use RFC 7807-style problem details with a stable `code`, a `traceId`, and field-level validation errors where applicable.

## Dashboard

### `GET /dashboard`

Returns queue counts, latest ingestion status, source health summary, provider health summary, topic distribution, and seven-day activity.

## Sources

### `GET /sources`

Query: `enabled`, `kind`, `health`, `page`, `pageSize`.

### `GET /sources/{id}`

Returns a source definition with secret fields redacted.

### `POST /sources`

Creates a source definition. Connector-specific settings are validated by the selected connector.

### `PUT /sources/{id}`

Replaces editable source fields while retaining run history.

### `POST /sources/{id}/test`

Performs a bounded health/fetch test and returns no more than three normalized previews.

### `POST /sources/{id}/enable` / `POST /sources/{id}/disable`

Explicit state commands to avoid accidental full replacement.

## Ingestion

### `POST /ingestion/runs`

Body:

```json
{
  "sourceIds": [],
  "force": false,
  "generateDrafts": false,
  "maxCandidates": 20
}
```

Returns `202 Accepted` with a run ID.

### `GET /ingestion/runs/{runId}`

Returns status, counters, source results, warnings, and errors.

### `POST /ingestion/runs/{runId}/cancel`

Requests cooperative cancellation.

## Content items

### `GET /items`

Query: `query`, `topic`, `sourceId`, `minScore`, `status`, `from`, `to`, `sort`, `page`, `pageSize`.

### `GET /items/{id}`

Returns normalized content, provenance, score breakdown, topic matches, related/duplicate items, and draft links.

### `POST /items/manual`

Adds a manually curated item or URL metadata without crawling.

### `POST /items/{id}/promote`

Moves an item into the drafting candidates regardless of score, retaining the original score explanation.

### `POST /items/{id}/archive`

Archives the item without deleting provenance.

## Drafts

### `GET /drafts`

Query: `status`, `channel`, `topic`, `recipeId`, `page`, `pageSize`.

### `POST /drafts`

Body:

```json
{
  "contentItemIds": ["item-id"],
  "recipeId": "linkedin-explainer",
  "providerRoute": "default",
  "instructions": "Optional one-off direction"
}
```

Returns `202 Accepted` with a generation run ID.

### `GET /drafts/{id}`

Returns the latest revision, references, claims, diagram, validation results, and generation metadata.

### `PUT /drafts/{id}`

Saves an edited revision using optimistic concurrency (`revision` or `ETag`).

### `POST /drafts/{id}/regenerate`

Body selects fields: `hook`, `body`, `diagram`, `hashtags`, or `all`. Existing approved fields are not overwritten unless explicitly selected.

### `POST /drafts/{id}/validate`

Runs channel, claim, reference, and diagram validation without changing status.

### `POST /drafts/{id}/approve`

Requires the latest revision and all blocking validations to pass.

### `POST /drafts/{id}/reject`

Requires a short reason; preserves the draft for learning and duplication avoidance.

### `POST /drafts/{id}/mark-published`

Records manual publication metadata: channel, URL, and published time. It does not call a social network.

### `GET /drafts/{id}/export?format=plain|markdown|json|mermaid|svg`

Returns an export artifact. PNG is created in the browser in v1; a server renderer can be added later.

## Topics and recipes

### `GET /topics`
### `PUT /topics`
### `POST /topics/validate`
### `GET /recipes`
### `GET /recipes/{id}`
### `PUT /recipes/{id}`

Configuration writes create a timestamped backup and increment the schema/config version.

## Providers

### `GET /providers`

Returns provider IDs, types, enabled state, capabilities, selected routes, and health. It never returns API keys.

### `POST /providers/{id}/test`

Runs a small structured-output health check with a configurable timeout.

### `PUT /providers/{id}`

Updates non-secret settings and the name of the environment variable containing a secret.

### `PUT /providers/routes`

Updates task routing and fallback order.

## Settings

### `GET /settings`
### `PUT /settings/profile`
### `PUT /settings/schedule`
### `PUT /settings/storage`

A storage-mode change that can discard data requires an explicit confirmation token generated by the API.

## Runs and activity

### `GET /runs`
### `GET /runs/{id}`
### `GET /runs/{id}/events`

The event endpoint may use polling initially and server-sent events later.

## Health

### `GET /health/live`

Process is running.

### `GET /health/ready`

Configuration is valid, workspace is writable when persistence is enabled, and required local dependencies are reachable.
